# PLI Service

Веб-сервис для учёта диагностик трубопроводов. Хранит обследования, пролёты, дефекты и вложения, показывает диагностики на карте и формирует отчёты.

## Локальный запуск

Понадобятся Docker и Docker Compose. Один раз создайте три разных секрета в каталоге с доступом только для владельца. Права файлов позволяют контейнерам прочитать смонтированные секреты при запуске от непривилегированного пользователя.

```sh
mkdir -p -m 700 secrets
(
  set -C
  for pli_secret in flask_secret_key db_owner_password db_app_password; do
    pli_secret_file="secrets/${pli_secret}.txt"
    if [ ! -e "$pli_secret_file" ]; then
      openssl rand -hex 32 > "$pli_secret_file" || exit
      chmod 644 "$pli_secret_file" || exit
    fi
  done
)
SESSION_COOKIE_SECURE=0 docker compose up --build -d
docker compose exec web flask --app app create-admin
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080), войдите и создайте первый участок в панели администратора. Порт можно задать через `PLI_HTTP_PORT`. Укажите `YANDEX_MAPS_API_KEY` для карты и ограничьте ключ по домену и квоте в кабинете Яндекса. Координаты также можно ввести вручную.

Для рабочего доступа разместите HTTPS-прокси перед локальным портом Nginx и используйте `SESSION_COOKIE_SECURE=1`. При задании `TRUSTED_HOSTS` включите рабочие домены и `127.0.0.1` для проверки готовности. Если перед Nginx добавлен ещё один прокси, настройте `real_ip` для его доверенного адреса, чтобы ограничение входа учитывало IP клиента. Используйте новый ключ сессий при переходе со старой версии.

## Права

| Роль | Просмотр и отчёты | Диагностики | Управление |
|---|---|---|---|
| Пользователь (`Viewer`) | Свой участок, включая карту, вложения и отчёты | Просмотр | Свой пароль |
| Редактор (`User`) | Все участки | Создание, изменение, удаление | Свой пароль |
| Администратор (`Admin`) | Все участки | Создание, изменение, удаление | Пользователи и участки |

Годовой отчёт использует дату обследования. Фотографии и PDF-вложения доступны по ссылкам из карточек после проверки прав. Вложения нового формата лежат в томе `uploads`. Команда `docker compose exec -T web flask --app app cleanup-files` повторно обрабатывает до 200 ожидающих удалений за запуск и удаляет истёкшие записи об ограничении входа. При сбое связи во время коммита новые файлы сохраняются до сверки с таблицей `diagnostic_attachments`.

## Перенос существующей базы

1. Остановите запись на старом стенде, экспортируйте БД PostgreSQL 13 через `pg_dump -Fc` и скопируйте `static/uploads`. Сохраните старый том и исходники для отката. Для первого прогона используйте копию данных и отдельное имя проекта Compose.
2. Запустите `docker compose up -d postgres`. Новый PostgreSQL 17 использует том `pgdata17`. Восстановите архив до запуска миграций, например `docker compose exec -T postgres pg_restore -U pli_owner -d pli_service --no-owner --no-acl < pli_service.dump`. Разместите старые вложения в `static/uploads`; эта папка используется как архив только для чтения.
3. Запустите `docker compose up --build -d`. Миграции выполняются сервисом `migrate` до старта приложения. Для дубликатов логинов или неизвестных ролей миграция остановится с ошибкой. Устраните такие записи на копии и запустите миграцию повторно.
4. Сверьте количество диагностик и суммы расстояний по участкам с источником. Сверьте отдельно количество и порядок пролётов, дефекты, фотографии и PDF. Запрос `SELECT * FROM diagnostic_migration_issues ORDER BY diagnostic_id, field;` показывает записи, требующие ручной сверки. Исходные поля остаются в БД. Диагностики с нераспознанной датой видны в списке и карточке. После корректировки даты они появятся в годовом отчёте. Старые пути вложений и недоступные файлы можно сверить с архивом.
5. Если использовался старый стандартный пароль администратора, миграция отключит эту учётную запись. Назначьте новый пароль через `docker compose exec web flask --app app create-admin --reset-disabled` либо создайте администратора с новым логином. Старые пользовательские хеши обновляются после подтверждённого входа.
6. Перед переключением трафика проверьте доступ по участкам и скачайте контрольные отчёты с кириллицей, фотографиями и приложенными графиками. При откате запустите прежнее приложение на старом томе и восстановите копию вложений. Записи после переключения потребуют отдельного переноса при откате.

## Проверки

```sh
python -m pip install -r requirements.txt pytest ruff
ruff check .
python -m pytest
```

Для тестового стенда можно создать демонстрационные записи командой `docker compose exec web flask --app app seed-diagnostics --area-id 1 --count 10`.

Для интеграционных проверок задайте `PLI_TEST_DSN` к тестовой базе PostgreSQL. Набор создаёт временную схему, применяет миграции к пустой и старой схеме и проверяет роли, сохранение формы, отчёты и отказ файловой операции. Для PDF нужны Pango и шрифт с кириллицей. В CI также выполняется аудит зависимостей.
